
# Lesson 2.7 — Hallucination Hunt

## Project

Zentrox Lab — AI Order Extractor

## Objective

Test whether the AI correctly extracts customer orders
without inventing customer names, services, quantities,
addresses, or prices.

Also test how Python validation handles invalid services
and incomplete AI extractions.

## Model Configuration

- Model: llama3.2
- Provider: Ollama
- Framework: LangChain
- Temperature: 0
- Output format: JSON schema
- Programming language: Python

## Test 3 — Mixed Valid and Off-Menu Items

**Customer message:**

"My name is Bilal. I need 1 pizza and 1 ecommerce website. Model Town."

**Expected extraction:**

- Customer: Bilal
- Pizza: 1 (off-menu item)
- Ecommerce website: 1 (valid service)
- Address: Model Town

**Expected Python behavior:**

- Reject pizza.
- Accept ecommerce website.
- Calculate 50,000 PKR.
- Print a CHECK warning for pizza.

### Initial Test — FAIL

AI classified the entire message as not an order.

**Actual output:**

    Not an order: needs a human reply.

**Problems found:**

- Valid ecommerce website order was missed.
- Off-menu pizza was not extracted.
- No CHECK warning was generated.
- Bilal's valid order was not saved.

**Finding:**

AI incorrectly rejected a message containing both valid
and invalid items.

### Improvement Applied

The extraction prompt was updated with instructions to:

1. Extract all requested items.
2. Include both menu and off-menu items.
3. Never reject an entire order because one item is invalid.
4. Set is_order to true when a customer requests a product
   or service.
5. Leave menu validation to Python.

### Retest 1 — FAIL

After updating the prompt, the first run still classified
Bilal's message as not an order.

**Actual output:**

    Not an order: needs a human reply.

**Finding:**

The improved instructions did not consistently resolve
the extraction issue.

### Retest 2 — PASS

The next run successfully extracted the valid and invalid
items.

**Actual output:**

    1 x ecommerce website = 50,000 PKR
    Customer: Bilal, Address: Model Town
    Total: 50,000 PKR
    CHECK: 'pizza' is not on the menu.

**Result:** PASS

**Finding:**

AI extracted both items.

Python rejected pizza because it was not present in the
official PRICES dictionary.

The valid ecommerce website order was accepted and saved.

**Important observation:**

The same code and model configuration produced different
results across runs.

Temperature 0 reduces randomness but does not guarantee
identical or correct AI outputs.

## Hallucination and Validation Findings

### 1. Customer Name Validation

Python checks whether the extracted customer name
appears in the original customer message.

If the name cannot be verified, the program generates
a CHECK warning.

### 2. Menu Validation

Python checks extracted services against the PRICES
dictionary.

Services not found in the menu are rejected.

**Observed example:**

    CHECK: 'pizza' is not on the menu.

### 3. Quantity Validation

Python rejects quantities that are not positive integers.

This helps prevent invalid order calculations.

### 4. Price Validation

AI does not calculate the final price.

Python calculates each line total using:

    line_total = PRICES[name] * quantity

This prevents the program from trusting AI-generated prices.

### 5. Missing Valid Items

The Bilal test demonstrated that AI can completely miss
a valid service.

Python cannot validate an item that the AI never extracts.

### 6. Inconsistent AI Output

The same mixed-order message was rejected in one run
and successfully extracted in another.

Structured JSON and temperature 0 do not guarantee
reliable extraction.

### 7. Invented Information

No invented customer names or prices were observed
in the successful terminal outputs.

However, additional tests are needed to confirm that
the model consistently avoids invented information.

## Conclusion

The AI Order Extractor successfully processed normal orders,
multiple-service orders, and Roman Urdu messages.

The final retest extracted four valid orders worth
230,000 PKR and correctly rejected the off-menu pizza item.

However, the mixed-order test was inconsistent across runs.

This experiment demonstrates three important lessons:

1. AI-generated structured JSON can still contain mistakes
   or missing information.

2. Python validation is necessary to reject unsupported
   services and calculate prices reliably.

3. Prompt improvements can help extraction, but repeated
   testing and additional safeguards are necessary.

The final retest passed, but the observed inconsistency
should be addressed before using this system for real
customer orders.
